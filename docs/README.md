# Docs

| Folder | What is in it | Read it when |
|---|---|---|
| `problem/` | The brief (verbatim), requirements and where each is met, domain primer, tender facts, sample data | You need to know what was asked or what a term means |
| `solution/` | The design (`SOLUTION.md`), decision log, data extraction diagram | You are building or explaining how it works |
| `phases/` | The plan, the current phase (`status.json`), one doc per phase with reviewer Q&A | You are starting, checking or closing a phase |
| `product/` | Why a developer would pay, pricing (draft) | Writing the README product page, the call |
| `EXPLAINED.md` | The solution and the evals in simple English | First read, or before the call |
| `RUNBOOK.md` | Running, checking and fixing the app | Something does not start |

Reading order for a reviewer: `../README.md`, `EXPLAINED.md`, `solution/SOLUTION.md`, the latest `phases/phase-N.md`.

Raw notes (call notes, chat exports) go in `/notes`, which git ignores. Only distilled, checked
content belongs here.
